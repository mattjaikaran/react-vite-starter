# Agent instructions

Single source of agent instructions for this repository. No nested `AGENTS.md`
exists; `CLAUDE.md`, when one is added, contains only `@AGENTS.md`. Read
[`README.md`](./README.md) for setup and feature details and
[`DESIGN.md`](./DESIGN.md) before changing the interface. Tool procedures live in
`.claude/skills/<name>/SKILL.md`; this repository ships the React Doctor skill.

## Project overview

React 19 single-page starter: Vite 5, TypeScript 5.5 (strict), React Router v7,
TanStack Query 5, TailwindCSS 3, oxlint/oxfmt, Bun. Authentication is a context
in `src/lib/auth.tsx` using bearer JWTs persisted in `localStorage`; see the
security notes in `README.md`.

- `src/lib/` — API client (`api.ts`), auth context, theme resolution, utilities.
- `src/components/ui/` — shared primitives; `src/components/` — layout and guard.
- `src/pages/` — route components; `src/App.tsx` — route table.
- `e2e/` — Playwright browser specs; `scripts/` — repository gates.
- [`DEPENDENCIES.md`](./DEPENDENCIES.md) — every pinned dependency;
  [`DESIGN.md`](./DESIGN.md) — design contract.

## Commands

Requires Bun >= 1.3.0 (`bun.lock` is generated by Bun 1.4) and Node
^20.19.0 || >=22.13.0. Do not use npm or yarn.

```sh
cp .env.example .env   # optional; API requests proxy to localhost:8000
bun install            # install pinned dependencies
bun run dev            # Vite dev server on http://localhost:5173
bun run build          # tsc && vite build into dist/
bun run preview        # serve the production build
bun run lint           # oxlint
bun run lint:strict    # oxlint, warnings are failures
bun run lint:fix       # apply safe lint fixes
bun run format         # oxfmt --write .
bun run format:check   # verify formatting
bun run typecheck      # tsc --noEmit
bun run test           # Vitest unit suite
bun run test:e2e       # Playwright against the dev server
bun run test:e2e:ui    # Playwright UI mode
bun run doctor         # React Doctor, blocking on errors
bun run check-conventions
bun run check-dependencies
bun run check-agent-docs
bun run gauntlet       # lint, typecheck, test, all three checks
```

`.github/workflows/ci.yml` runs Oxlint (`lint:strict`), Oxfmt (`format:check`), React
Doctor (`doctor`), convention/dependency checks, typecheck/unit tests, build, e2e and the
agent-docs gate on self-hosted runners.
Markdown-only changes skip the code jobs but still run `check-agent-docs`.

## Code standards and architecture

- Keep TypeScript strict: no `as any`, no `@ts-ignore`/`@ts-expect-error`
  (`scripts/check_conventions.ts` enforces both).
- Components use named exports only (no `export default`). Reuse
  `src/components/ui/` primitives instead of new component systems.
- All HTTP goes through `src/lib/api.ts`; never import axios or call `fetch` in
  components. Server state belongs in TanStack Query hooks.
- Forms use React Hook Form with Zod resolvers, not `useState` field state.
- Navigation uses `react-router-dom` (`useNavigate`, route elements); never
  assign `window.location.href`.
- Colors, spacing and states come from the semantic tokens in `src/index.css`
  and `tailwind.config.js`. The appearance and palette invariants in
  `DESIGN.md` are binding; do not add page-local theme colors.
- Dependencies are pinned exactly in `package.json`, documented in
  `DEPENDENCIES.md`, and committed together with `bun.lock`.

## Testing policy

- Vitest covers pure utilities (`src/lib/utils.test.ts`) and isolated
  primitives (`src/components/ui/Image.test.tsx`), configured in
  `vite.config.ts`.
- Playwright covers routes, navigation, appearance, and account flows in
  `e2e/`, driven by `playwright.config.ts` against `bun run dev`.
- A change to browser behavior extends the matching e2e spec; do not add a
  second suite for the same surface.
- Verify the actual surface: run the app or browser checks. A passing build is
  not visual verification, and never report a command you did not run.

## Git and commits

- Conventional Commits: `type(scope): Imperative summary`; subject at most 50
  characters, body wrapped at 72. Stage explicit paths, not `git add -A`.
- One logical change per commit. Do not rewrite or force-push shared branches.
- Never commit secrets: `.env`, `.env.local` and `.env.*.local` are ignored, and
  `.env.example` documents the variables. `check-agent-docs` fails on a tracked
  environment file.
- Never commit `dist/`, `coverage/`, `test-results/` or `playwright-report/`;
  they are generated and gitignored, and `check-agent-docs` fails when tracked.

## Spec workflow (agent-run)

- Each change starts from one spec in `tasks/specs/<issue>-<slug>.md`.
- The spec's **files owned** list and **gate** are defined in
  [`tasks/specs/README.md`](./tasks/specs/README.md); follow both and report the
  gate's real output in the pull request.

## Security

- Access and refresh tokens live in `localStorage` by design; the XSS tradeoff
  and the backend cookie alternative are documented in `README.md`. Never log
  tokens, credentials, or user data.
- Send requests only through `src/lib/api.ts` with `VITE_API_URL` or the
  development proxy; never hardcode hosts or production URLs.
- Do not add `dangerouslySetInnerHTML`, telemetry, or analytics without an
  explicit requirement and a security review.
